# Errors found, and how the design surfaced them

Every item below was found by a **generic rule** in `src/server/checks/rules.ts`. Each rule describes a class of mistake and looks for it across documents, extracted values, client answers and agency records. Nothing encodes this household's answers. `tests/checks.test.ts` proves each rule fires on the real packet issue with the right numbers.

**Tax effect** is the change in the amount owed (positive = owes more), at v3 rates. *est.* = change × the version's published per-dollar rate (the engine will refine). *exact* = an engine what-if result. *1:1* = a payment or credit. For items fully California-source (a sale during CA residency, a wage split), the CA effect uses `ca_source_income`, as the packet README instructs. "Resolution" is what the workpaper proposes: a one-click suggested fix that becomes an adjustment (original kept, reason, approver). Judgment calls require an authority.
